# PilotBioSci Web Application

A React (Vite) storefront with an Express/MySQL backend, deployed as a single
Node.js application: Express serves both the built frontend and the `/api/*`
routes from one process.

## Project structure

```
.
├── src/              React frontend source
├── public/           Static assets (images, etc.)
├── dist/             Built frontend (generated by `npm run build`, not committed)
├── server/           Express backend
│   ├── server.js     Main server entry point — serves dist/ and the API
│   └── .env          Backend environment variables (not committed — see server/.env.example)
├── .env.example      Frontend dev-mode environment variables
└── package.json      Root scripts orchestrate both frontend build and backend start
```

## Running locally

You need Node.js 18+ and a local MySQL server.

1. **Install frontend dependencies** (from the project root):
   ```
   npm install
   ```

2. **Install backend dependencies**:
   ```
   cd server
   npm install
   cd ..
   ```

3. **Configure the backend**: copy `server/.env.example` to `server/.env` and
   fill in your local MySQL credentials and a `JWT_SECRET`. The server creates
   its own tables automatically on first run — no manual migration needed.

4. **Create the MySQL database** (matching `DB_NAME` in `server/.env`):
   ```sql
   CREATE DATABASE pilotbiosci;
   ```

5. **Run the backend** (terminal 1, from project root):
   ```
   cd server
   npm start
   ```
   Listens on `http://localhost:4000` by default.

6. **Run the frontend** (terminal 2, from project root):
   ```
   npm run dev
   ```
   Opens on `http://localhost:5173` and proxies `/api/*` calls to the backend.

## Building and running as one unified app (production-style)

This is how it will run on Hostinger, and you should test it this way before
deploying:

```
npm run build   # builds the frontend into dist/, then installs server deps
npm start        # starts Express, which serves dist/ AND the API on one port
```

Then visit `http://localhost:4000` — the whole app, frontend and backend,
runs from that single port/process.

## API routes

- `POST /api/auth/register` — `{ username, password, email }`
- `POST /api/auth/login` — `{ username, password }`
- `POST /api/auth/logout`
- `GET  /api/auth/me` — current user from the httpOnly session cookie
- `POST /api/auth/forgot-password` — `{ email }`
- `POST /api/auth/reset-password` — `{ token, email, newPassword }`
- `POST /api/inquiry` — `{ name, email, phone, company, country, productId, productTitle, message }`
- `POST /api/orders` — requires auth; `{ items, shipping, delivery, currency }`

## Notes

- Auth uses an httpOnly `token` cookie (JWT), not localStorage.
- In production (`NODE_ENV=production`), the server redirects HTTP requests
  to HTTPS and sets the `Strict-Transport-Security` header.
- Failed login attempts lock an account for 30 minutes after 5 failures.
- Order pricing is currently computed and stored, but no payment processor is
  integrated yet — orders are created with `status = 'pending_payment'`.
